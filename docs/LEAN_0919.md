# 以 0919 舊版為基底優化：Render 精簡測試版

版本：`2026.10.23-lean-0919`。

以使用者提供的 `更新版本/0919/bot.py` 的功能流程與「操作時讀取訂單」架構為基底重新整合，移植現行版已測試的非同步讀寫、權限、限流及結單保護；並非逐行還原舊檔。原始檔 SHA-256：`a977dd43d3ae6a690c0a77ead054e3a63a69efa69bc4ace981b0727affe18326`。

## 執行方式與保留功能

啟動指令仍為 `python -u -m src.bot`，相依套件與 Sheets 工作表名稱不變，保留名冊綁定、開團、修改截止時間、訂購、取消、查訂單、湊單進度、結單、匯款與對帳功能。保留管理員刷新指令，並可觸發待處理通知恢復。

## 這次精簡

- 不再維護全域完整訂單快取；各項操作按需從 Orders_Temp 讀取，讀完釋放操作區域資料。並非將所有歷史結算載入記憶體。
- 名冊、商品、系統設定保留小型快取；名冊商品在下一次操作超過 60 秒時才重新載入，同時操作共用一次更新。管理員可立即刷新。
- 停用 Discord 一般訊息快取 `max_messages=None`，不影響 slash／表單／按鈕流程。
- 移除每 30 秒的閒置通知輪詢與 Render 自我喚醒。UptimeRobot 可繼續監控 HTTP 首頁。
- 通知只在成功啟動、完成結單、管理員刷新後處理。每批最多 5 人，有待處理工作才延後 30 秒繼續；空佇列不繼續掃描。
- 通知掃描只讀狀態欄並批次讀取最多 5 份待寄內容；狀態只更新指定列。已寄送歷史不會被每批整張改寫。只快取工作表連線物件，不快取歷史帳單。
- 通知遇 Sheets／程式例外最多再排程 4 次，之後記錄錯誤，由管理員核對並刷新。Discord 429 依 Retry-After 等待，不反覆嘗試。
- 每 60 秒輸出 `Runtime memory`：程序 RSS、程序峰值 RSS、容器用量及限制。讀不到的欄位為 null。容器用量與程序 RSS 不同，不能混為一談。
- 首頁與 /readyz 顯示版本，便於確認實際執行的程式。

## 必須保留的訂單保護

- 初始 defer 成功後才進行 Sheets 操作，所有同步 Sheets 工作移至執行緒並序列化。
- 相同 interaction ID 不重複追加訂單；回應不明確時不盲目重送。不同次送出仍可能是不同訂單，須人工核對。
- 使用唯一歷史／結算工作表名稱，不刪除同日舊報表。
- 備份、結算報表及通知佇列讀回驗證成功後，才清理當期訂單；失敗保留來源與恢復檢查點。
- `sending` 中斷後標記 uncertain，不自動重寄。Google Sheets 不是跨主機交易資料庫，始終只運行一份 Bot。
- 通知佇列若被人工插入／移動列，寫入前核對 delivery_id；不對錯列更新。請勿刪除通知表、改欄位順序或將 uncertain 全部改成 pending。

## 測試與部署驗收

本機離線測試涵蓋 50 項，包括既有 35 項回歸及 15 項精簡版測試。測試用模擬 Sheets／Discord，不存取正式帳務；包含本機 HTTP 測試。

部署前確認 Google Cloud VM 已停止。Render 使用 Free、main、Root Directory 留空、Build `pip install -r requirements.txt`、Start `python -u -m src.bot`。沿用既有 DISCORD_BOT_TOKEN、GOOGLE_CREDS_JSON 與試算表；不需重設 Token。

驗收順序：登入成功 → Discord READY → DATA READY → COMMANDS READY → 首頁版本正確 → 真實 `/我的訂單` 的 defer／followup 成功。再由使用者選擇測試團期驗證下單、取消、結單與私訊，避免將測試資料混入正式團期。

確認 `Runtime memory` 在啟動、同時操作、結單時的峰值；50 項離線測試不保證所有實際負載都低於 512 MB，也不保證更換程式會解除 Render 出口 IP 的 Discord 限制。

若需回復，Render 可重新部署上一個成功版本；先停止另一邊的 Bot。此變更沒有刪除舊 Sheets 資料，也沒有停用原有恢復檢查點。
