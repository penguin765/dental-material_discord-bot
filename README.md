# 牙材 Discord Bot｜班級使用指南

這個機器人協助全班訂購牙材，並用 Google Sheets 保存訂單與結算資料。流程是：**牙材長開團 → 同學下單 → 截單結算 → 同學匯款給小組長 → 小組長對帳並上繳 → 牙材長確認收款**。

> 使用指南草稿 v1：依目前程式的實際功能撰寫。收款帳號、付款期限、領貨時間與地點，請以班級及牙材長公告為準；機器人不會自動轉帳或核對銀行入帳。

## 快速找到你的操作

| 身分 | 主要操作 |
| --- | --- |
| 全班同學 | 綁定名冊、訂購、查詢與取消訂單、查看湊單進度、回報個人匯款 |
| 小組長 | 同學的操作，加上組內對帳、確認個人入帳、回報整組上繳 |
| 牙材長 | 同學的操作，加上刷新資料、開團、修改截止時間、關團、確認各組上繳 |

**權限由 Google Sheets 的 Members 名冊決定。** Discord 暱稱或伺服器身分組名稱不會自動授予管理權限。牙材長與小組長須由管理員預先填好 Discord 使用者 ID；牙材長若也要做組內對帳，名冊職位需同時包含「小組長」。

在班級 Discord 伺服器的指令輸入框輸入 `/`，選擇機器人的指令，再填寫欄位。以下範例的姓名、組別、日期及末五碼都是示意，請換成自己的資料。

## 同學：從第一次使用到繳費

### 1. 綁定名冊（首次使用）

執行 `/綁定名冊`，在「真實姓名」填入名冊上的姓名，例如：

```text
/綁定名冊 真實姓名:王小明
```

收到綁定成功訊息後即可下單。只綁定自己的姓名；若找不到姓名、同名、已被其他帳號綁定或需要更換帳號，請聯繫牙材長／管理員。小組長與牙材長不能用姓名自行認領管理職位。

### 2. 開團期間訂購

1. 執行 `/訂購牙材`。
2. 在其中一個商品選單勾選品項，每次最多 5 項。
3. 在彈出表單填入各品項的**正整數數量**，例如 `1`、`2`，再送出。
4. 確認收到「成功加入暫存訂單」，再用 `/我的訂單` 核對品項、數量與總額。

商品分區顯示時，可分次選購其他區的商品。再次送出訂購會**新增訂單**，不會覆蓋原有數量；想把 2 個改成 3 個，請先取消原訂單再重新下單。

### 3. 查詢、取消與修改數量

- `/我的訂單`：查看本期暫存明細，從取消選單選取一筆即可取消該筆訂單。
- 修改數量：取消原筆，確認取消成功，再執行 `/訂購牙材` 重新下單。
- `/團購進度總覽`：查看全班各品項的數量與最低購買量。

以上三項操作都限開團期間。選單約 5 分鐘後過期，或機器人重啟後，請重新執行指令取得新選單。

**最低購買量是全班合計門檻。** 例如某商品最低 10 個，截單時全班只訂 8 個，該品項會被淘汰，不列入個人應繳金額。購物車金額是截單前的預估，請等結算後再付款。

### 4. 截單後付款與回報

1. 等待牙材長確認本期結算完成。機器人會安排寄送個人帳單私訊；若未收到，請找小組長查結算報表。
2. 依結算應繳金額，匯款給**自己的小組長**，帳號以小組長公告為準。
3. 匯款後執行 `/回報匯款`，填入轉出帳戶的末五碼，例如：

```text
/回報匯款 末五碼:01234
```

末五碼必須是 5 位半形數字，開頭的 0 也要保留。回報後狀態為「已匯款待審核」，須由小組長核對實際入帳後確認為「✅ 已收妥完款」。

回報只會寫入**最新結算表**，不能指定舊期。請先確認是哪一期帳款；已確認收款後不要再次回報，重送會覆寫末五碼並把狀態改回待審核。需更正時請先通知小組長。

## 小組長：收款、對帳與上繳

### 1. 確認自己的名冊資料

請管理員在 Members 預填你的 Discord 使用者 ID、姓名、組別及包含「小組長」的職位，並請牙材長刷新資料。自己的牙材訂單也照同學流程操作。

### 2. 核對同學的付款

1. 執行 `/組內對帳`，預設顯示自己的組別。
2. 查看每位同學的應繳金額、回報末五碼及狀態。
3. **先查銀行實際入帳紀錄**，核對金額與末五碼。
4. 在選單勾選已確認入帳的同學（可複選），系統會更新為「✅ 已收妥完款」。
5. 重新執行 `/組內對帳` 檢查結果。

確認選單只列出待審核的同學。若尚未回報，請同學先完成回報；金額不符或無法辨識時，先聯繫本人。

代班時可指定組別，例如：

```text
/組內對帳 指定組別:2
```

目前程式允許小組長跨組查詢與確認，代班前請先與該組小組長協調，避免重複處理。

### 3. 將整組款項上繳牙材長

核對全組應繳總額並確認款項收齊後，依牙材長公告帳號轉帳，再回報**小組長轉給牙材長那筆交易**的轉出帳戶末五碼：

```text
/小組上繳匯款 末五碼:56789
```

代班可加填 `指定組別:2`。回報後等待牙材長確認；此指令只登記回報，程式不會檢查全組是否已收齊，也不會執行轉帳。已確認後若需更正，先聯繫牙材長，避免重送將狀態改回待審核。

## 牙材長：每一期團購的操作

### 1. 開團前準備

- 與管理員確認 Members 的姓名、組別、職位及管理職位使用者 ID。
- 在 Products 確認本期品項、單價與最低購買量，再執行 `/刷新名冊與商品庫`。
- 開團前確認商品資料正確；收單期間避免改價或更換品項 ID，因暫存訂單保存下單金額，結算又會參照當時的商品資料。
- 公告收款方式及聯絡窗口；小組長須能取得結算資料，但不必將含姓名及匯款末五碼的試算表公開。
- 確認上期已結算完成。付款指令只操作最新結算表，建議完成上期收款核對後再產生下一期結算。

### 2. 在公告頻道開團

在希望接收團購公告的文字頻道執行：

```text
/開團訂購牙材 截止時間:2026-10-30 23:59
```

格式固定為 `YYYY-MM-DD HH:MM`，採**台灣時間（UTC+8）**，且必須是未來時間。請換成本期實際日期。

此頻道會成為本期公告頻道。系統安排到期自動截單；若設定時距截止超過 3 天，會安排截止前 3 天提醒尚未達最低購買量的品項。請確認開團成功及頻道公告。

### 3. 收單期間管理

- 用 `/團購進度總覽` 追蹤湊單。
- 修改截止時間請用 `/修改截止時間`，填寫「新截止時間」，格式與開團相同；系統會重排截單／提醒並公告。
- 名冊或商品表變更後用 `/刷新名冊與商品庫` 重新載入資料。
- 提早截單才用 `/強制關團`：此指令會立即停止下單並在背景結算，請先告知同學。

### 4. 截單後核對報表

自動截單或強制關團後，等待完成公告，並核對 Google Sheets：

| 資料 | 用途 |
| --- | --- |
| 歷史原始明細 | 保存本期原始訂單，供追查 |
| 結算表區塊 A | 向廠商叫貨總表；只採購標示「達標成團」的品項，淘汰品項不應叫貨 |
| 結算表區塊 B | 各同學成功成團明細、應繳總額、匯款末五碼與小組長確認狀態 |
| 結算表區塊 C | 各組應上繳總額、上繳末五碼與牙材長確認狀態 |

成功結算後，Orders_Temp 會清除訂單資料並保留表頭；同學不能再用 `/我的訂單` 查看該期暫存資料。無人下單時不產生新報表，最新結算表設定可能仍指向舊期，請勿誤用舊表收款。

帳單私訊可能延遲或因隱私設定失敗，**以本期結算工作表為帳務依據**，必要時請小組長協助通知。

### 5. 確認各組上繳

執行 `/全班帳務總覽`，查看各組應繳金額及回報。實際核對銀行入帳後，在選單勾選已收到款項的小組，更新為「✅ 已收妥完款」，再重新執行指令核對。待審核選單不代表銀行已驗證入帳。

## 常見狀況

| 狀況 | 處理方式 |
| --- | --- |
| 找不到斜線指令或機器人沒回應 | 確認在正確伺服器並選到本機器人；請管理員確認在線、指令同步與權限。初始化或限流時依提示等待，不要連續重送 |
| 顯示權限不足 | 請管理員核對 Members 的 Discord 使用者 ID 與職位，再請牙材長刷新；只改 Discord 暱稱不會生效 |
| 目前非訂購期間 | 等待牙材長開團；已截單請向小組長查本期結算 |
| 選單失效或資料看起來舊 | 重新執行指令；仍不正確請牙材長刷新並核對資料 |
| 訂單結果尚未確認 | 不要立刻重送；請牙材長刷新並核對 Orders_Temp，確認原筆是否寫入 |
| 匯款回報找不到紀錄 | 確認已完成本期結算、有成功成團品項，且姓名與組別正確；找小組長核對 |
| 未收到帳單私訊 | 請小組長查本期結算表，不要用截單前購物車金額猜測應繳金額 |
| 結算失敗 | 牙材長先備份並聯繫管理員；修復後用 `/強制關團` 接續，不要刪除暫存、歷史表或 PENDING_SETTLEMENT |

商品選單目前最多顯示 125 項；個人取消選單及對帳確認選單每次最多列出 25 筆。可重新執行指令取得更新後選單；仍找不到要操作的資料時，請管理員協助核對。

## 管理員與部署參考

以下保留原有維運說明，供接手部署、試算表設定及故障恢復時使用。

使用 Discord 斜線指令及 Google Sheets 管理團購。請只執行一個 bot 程序；目前以單一程序的鎖保護訂單與結算，不支援多個 Render instance 共用同一份試算表。

## 2026-10 修正與原因

| 問題 | 修正 |
| --- | --- |
| Render 顯示 live，但不知道 Discord 登入卡在哪 | 啟用 discord.py INFO logging、每 60 秒記錄狀態、提供 `/readyz` |
| 初始化失敗後不再重試 | 成功載入並恢復狀態後才標記完成，失敗每 30 秒重試 |
| 換 bot 或同步暫時失敗後缺少指令 | 同步標記依 application ID 分開保存，失敗重試 |
| 網路回覆遺失時重複下單 | 不盲目重播寫入；同一 interaction 使用穩定 Order_ID；寫入前核對 ID |
| 同步執行緒逾時後仍在寫入 | HTTP 層設定 10 秒連線／30 秒讀取逾時；取消協程時等待 worker 結束後才放鎖 |
| 結算重試刪除歷史報表 | 唯一報表名稱、覆寫同一期固定範圍並讀回驗證，不刪除歷史工作表 |
| 清空訂單後結算中斷無法恢復 | 保存 PENDING_SETTLEMENT；已驗證階段從歷史明細恢復；保留 Orders_Temp 表頭 |
| 開團與關團狀態互相矛盾 | 下單只用統一檢查；未完成結算禁止開新團；開團與結算使用同一把鎖 |
| 舊選單失效無提示 | 5 分鐘逾時後停用選單並提示重新執行指令 |
| 可冒領管理職位 | 牙材長／小組長必須由管理員預先填入 Discord_User_ID |

## Render 設定

1. 合併修正 PR 後，確認服務部署的是該 commit。
2. Build Command：`pip install -r requirements.txt`
3. Start Command：`python -u bot.py`。不要用 `gunicorn bot:app`，那只會載入 Flask，不會執行 Discord 啟動點。
4. Python 固定為 `.python-version` 的 `3.14.3`，與先前提供的部署環境一致；若 Render 已設定 `PYTHON_VERSION`，請確認一致。
5. 設定下列環境變數：
   - `DISCORD_BOT_TOKEN`：Discord Developer Portal 的 Bot token。
   - `GOOGLE_CREDS_JSON`：完整 service account JSON，不要額外包外層引號。
   - `SPREADSHEET_ID`：建議填入 Google Sheet 網址 `/d/` 與 `/edit` 之間的 ID。
   - `SPREADSHEET_NAME`：未提供 ID 時使用，預設 `牙材_discord_bot`。
6. 將試算表分享給 service account 的 `client_email`，權限為編輯者，並啟用 Google Sheets API；以名稱查找時也需要 Drive API。
7. 保持單一 instance，勿同時在本機和 Render 啟動同一套訂單程式。Render 部署切換時先避免下單／結算。

`/` 是程序存活頁面，永遠可正常回應不代表 bot 已可用。`/readyz` 只有 Discord、資料及指令都就緒才回傳 200，否則 503。可用它檢查業務就緒；不要把外部 API 短暫失效直接變成不斷重部署的觸發器。

免費 Render Web Service 可能休眠或重啟；自我 ping 不能保證持續在線。正式收單應使用能持續運行的服務。程式保留 Flask 以符合 Web Service 的 PORT 要求。

## Google Sheets 表格

必須有 `Members`、`Products`、`Orders_Temp` 三個工作表。`System_Config` 可自動建立。

- Members：`Discord_User_ID`、`姓名`、`組別`、`職位`。綁定程式目前要求 ID 在 A 欄、姓名在 B 欄。
- Products：`Item_ID`、`品項名稱`、`單價`、`最低購買量`。單價請使用非負整數，不要填貨幣符號或千分位文字。
- Orders_Temp：`Order_ID`、`Discord_User_ID`、`姓名`、`組別`、`Item_ID`、`購買數量`、`單項總價`，依此順序放在第一列。

Discord_User_ID 欄設定為「純文字」後再貼入 ID，以免長整數精度遺失。已經被試算表四捨五入的 ID 必須重新填入；程式無法還原。

牙材長／小組長由管理員在 Members 預先填好 ID。Discord 開啟開發者模式後，可複製使用者 ID。一般學生仍可依姓名自行綁定，因此姓名必須唯一；這是信任班級成員的設計，不適合開放陌生人加入的公開伺服器。

## Discord 設定與驗收

1. 以 `bot` 和 `applications.commands` scopes 邀請至伺服器。
2. 授予公告頻道的 View Channel、Send Messages、Embed Links；不要為排錯盲目開啟所有管理員權限。
3. 目前使用預設 intents；斜線指令不要求 Message Content intent。
4. 部署 Logs 應依序出現：
   - `Starting Discord client`
   - `Discord REST login succeeded`
   - `Discord READY`
   - `DATA READY`
   - `COMMANDS READY`
5. 先使用測試試算表及測試頻道：刷新名冊 → 開團 → 訂購 1 項 → 我的訂單 → 取消 → 再下單 → 強制關團 → 核對歷史與結算表 → 回報匯款 → 對帳。
6. 關團後 Orders_Temp 應保留第一列表頭；歷史明細與結算報表應存在。測試同一天第二次開團，確認第一期報表仍保留。

## 排錯與恢復

- 只看到 Flask 200：查看 Discord logging；HTTP 網站正常不足以確認 Gateway 連線。
- Token rejected：檢查 DISCORD_BOT_TOKEN，使用 Bot token，不是 client secret。
- 429：依實際 HTTP 狀態與 Retry-After 等待，不因猜測共用 IP 而頻繁重啟。
- Google Sheets cache load failed：查看 traceback 的權限、JSON 或表頭錯誤；程式每 30 秒重試初始化。
- 訂單結果尚未確認：不要立刻重複送單。牙材長先刷新快取，再核對 Orders_Temp 的 Order_ID。不同次送出是不同 interaction，不能自動判定是否為重複購買。
- 結算失敗：保留 PENDING_SETTLEMENT 和所有歷史表，修復連線／資料問題後執行 `/強制關團` 接續。不要手動清空暫存或刪除備份。
- 若驗證失敗且曾手動編輯半成品報表，先備份、核對原始訂單與報表。程式會停止清理，避免資料遺失。
- 私訊可能因使用者隱私設定失敗；以結算工作表為帳務依據。

尚存限制：試算表不是交易資料庫；跨程序並行不受本機鎖保護；報表與通知不是原子交易；互動訊息在服務重啟後需重新執行指令。商品選單最多顯示 125 項、個人取消選單最多 25 筆；更多資料需後續加入分頁。一般姓名綁定仍需班級管理員監督。
